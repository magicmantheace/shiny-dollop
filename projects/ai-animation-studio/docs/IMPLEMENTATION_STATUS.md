- F3 slice 1 — local LLM adapter interface + bounded planner (2026-11-03): `studio/director.py` defines the adapter protocol (`propose(context) -> candidate scene`; adapter output is untrusted data, never commands) with two adapters — `StubAdapter` (deterministic, offline; stages the context's cast + lines, speak beats spaced by the ADR-009 speak-hold derivation) and `HttpAdapter` (local Ollama-style `/api/generate` via stdlib urllib; loopback endpoints only, non-loopback refused at construction; injectable `transport` callable; fenced/bare JSON extraction; `AdapterError` on transport failure, non-JSON replies or missing fields). `plan_scene` is the bounded planner: every candidate passes full `validate_scene` + IPC `wrap_scene` validation before acceptance, refusals are recorded in order and fed back to the next attempt under the context's `rejection` key, retries are bounded by `max_attempts` (default 3), and on exhaustion the stub's scene is returned marked as a fallback (`PlannerError` only when even the fallback cannot validate). - F3 slice 2 — offline TTS cache + phoneme timing (2026-11-03): `studio/voice.py` defines the voice engine interface (`synthesize(line, voice, timing, duration_ms=None) -> ClipResult` carrying WAV bytes, duration and engine name; engines never write files and never touch the network) with two engines — `StubVoiceEngine` (deterministic, offline: a valid silent WAV at 16000 Hz 16-bit mono whose duration is EXACTLY the ADR-009 speak hold for the line under the given `TimingConfig`, explicit `duration_ms` honored the same way; 16 frames per millisecond makes every hold sample-exact) and `ExternalVoiceEngine` (the slot for a future espeak/piper-style CLI engine: an injectable `runner(argv, input_text) -> bytes`, `{voice}` substituted into the argv template, the line passed as the input text, `VoiceError` on runner failure or non-WAV output, and the clip duration read from the produced audio rather than assumed). `phoneme_table(line, hold_ms)` emits an ESTIMATED word-level alignment — one segment per word partitioning the hold proportionally to word length (largest-remainder distribution: contiguous, first starts at 0, last ends at exactly the hold) with a coarse viseme label per word from a small documented onset rule (digraphs first, then first letter; letterless words are `sil`) — the data path a blendshape-capable rig would consume; there is no acoustic analysis. `VoiceCache` stores clips as `<key>.wav` in a directory outside git (constructor argument, else `AI_ANIMATION_VOICE_CACHE`, else `<system temp>/ai-animation-studio/voice-cache`) keyed by SHA-256 of the canonical JSON of engine name, voice, line, timing rate + clamps and explicit duration; a repeat call returns the stored clip without re-synthesizing, and no index file is kept — the record (key, engine, voice, line hash, duration, WAV length + SHA-256, phoneme table) is reconstructed from the stored WAV, and a corrupt entry re-synthesizes. The new `studio speak` CLI command (`--line`, `--voice`, `--engine stub|external`, `--voice-cmd`, `--voice-cache`, `--rate`) prints the clip record and never touches the scene runtime files. Covered by `tests/test_voice.py` (external engine exercised only through fake runners; full suite 156 tests OK). **No real speech engine has run** — none exists on this VM (no espeak/piper/festival/flite), so every clip produced so far is stub silence at the correct duration, and a real-engine run is an owner-hardware item exactly like F3.1's live model. Visual lip sync remains blocked on the adopted Quaternius rig (no morph targets) and is not claimed; the F3 exit (2 actors converse autonomously without stalls on owner hardware) remains open.
- F3 slice 3 — dialogue runtime: speak interrupts, safe event queue, camera cuts (2026-11-03): `speak` gains an optional boolean `interrupt` field (validated in `studio/schema.py`, mirrored in `schemas/scene.schema.json`; absent means false). The schedule computation now has a single source of truth — `compute_schedule` in `studio/timing.py` — mirrored by the Godot preview: non-interrupt events keep the ADR-009 delay semantics exactly, while a speak with `interrupt: true` is never delayed — it starts at its `at_ms` and, when the actor's current hold window contains that start, truncates the window there (an interrupt at/after the window's end is a no-op; interrupts chain; later events are gated by the truncated window). Dispatch order at equal effective times is deterministic: camera first, then spawn, then the rest in scene index order. The preview logs a truncation distinctly (`Speak interrupted for <actor> at <ms>` + the revised window), an interrupted speak occupies only its truncated window, and dispatch of an event whose actor has no spawned node is skipped with a named `Dispatch skipped:` ERROR while the queue continues (a thin guard; load validation remains the gate). Covered by `tests/test_dialogue_runtime.py` (full suite 176 tests OK) plus VM headless evidence: (a) interrupt probe — a speak with an explicit 5000 ms hold at 0 ms is cut by an interrupting speak at 2000 ms, logging `Speak interrupted for solo at 2000 ms` and `Truncated speak hold for solo: window 0..5000 -> 0..2000 ms`, the first line occupying 2000 ms and the interrupting line playing with its derived 1534 ms hold; (b) same-timestamp probe — `Camera request: wide` logged before the speak line despite the camera event sitting later in scene order; (c) the standard demo replayed after the change with a log byte-identical to the pre-change baseline (holds 2934/2000 ms, same order, no new lines). All of this is VM headless evidence only; the F3 exit (2 actors converse autonomously without stalls on owner hardware) remains open and unclaimed.
- F4 slice 1 — animation layering + gaze/look-at (2026-11-03): `speak`/`emote`/`move` events gain an optional `look_at` field — exactly one of `{"actor_id": ...}` or `{"position": [x, y, z]}` — validated in `studio/schema.py`, mirrored in `schemas/scene.schema.json`, and refused on `spawn`/`camera`. `compute_schedule` passes the field through and computes the gaze window beside the schedule (speak: the occupancy window after any truncation; move: the duration window; emote: until the same actor's next event or the schedule end) without changing any scheduling value. In the preview, an approved-GLB actor now plays through two layers — a base `AnimationPlayer` (full-body clips) and an upper-body overlay player carrying copies of the same clips filtered to the `studio_humanoid_v1` upper-body bone set (spine chain, neck, `Head`, arms, fingers) — with the `speak` gesture routed to the overlay so the base clip (idle, or a walk in flight) is never interrupted; both players run in manual callback mode, advanced base-then-overlay in `_process` for a deterministic composition (chosen over an AnimationTree because the codebase already builds a merged library on a plain player, the filtered-second-player expresses the two-layer blend directly, and manual advance makes the composition order — and the gaze pose read after it — exact rather than engine-scheduled). Gaze turns the `Head` bone toward the target with yaw clamped to ±60° and pitch to ±30°, recomputed per frame from current positions, easing back to the animated pose at window end; capsule actors log `Gaze skipped: ... (no skeleton)` once per window and continue. Covered by `tests/test_gaze.py` (full suite 197 tests OK) plus VM headless evidence (see the F4 slice 1 Verified section): the standard demo is byte-identical to the pre-change baseline in its standard (capsule) configuration, and the GLB configuration differs only by the new F4.1 lines. **The F4 exit's visual parts — composite actions without visible severe clipping, on owner hardware — remain open and unclaimed**; headless logs prove scheduling, layer composition and gaze engagement, not on-screen appearance. Composite actions (pick-up/sit/drink) and prop sockets are F4.2, not this slice; `emote` still has no clip dispatch (it logs only, as before), so the overlay's emote channel exists but carries nothing yet.
- F4 slice 2 — prop sockets + composite action macros (2026-11-03): scenes gain an optional top-level `props` registry (`{id, asset_id, position, socket?}` — socket `hand_r`/`hand_l`, default `hand_r`, the RIG_CONTRACT hand anchors) and one new op, `interact`, with `action` in {`pick_up`, `put_down`, `sit`, `drink`} and a required `duration_ms` (move wire bounds). Field rules (`prop_id` required for the prop actions and refused on `sit`; `target` required for `sit`, optional for `put_down`, refused elsewhere; `look_at` refused) and the holding sequence (one prop per actor, one holder per prop; `drink`/`put_down` require holding; checked in authored order) are enforced by `studio/schema.py` and mirrored in `schemas/scene.schema.json`. `compute_schedule` expands each composite deterministically into an occupancy window that gates later same-actor events like a speak hold (and is itself gated the same way), with a fixed phase model — pick_up: `reach` then attach at the window midpoint, `hold` to the window end, the attachment persisting until put_down; drink: one `consume` phase; put_down: `lower`, releasing at the window end; sit: `enter`, seated until the next move — and records `phases`/`attach_ms`/`release_ms`/`holding_after`/`seated_after` per event. The demo export attaches an ADR-008 pin per declared prop to the manifest's `props` section (status/version/SHA-256 from the library, like recipe files); the preview resolves props through it, places them at their declared positions, attaches a held prop to a `BoneAttachment3D` on the socket bone (the bone origin is the measured socket; no grip offset — per-prop grip offsets remain future work per RIG_CONTRACT), plays `pickup`/`consume`/`interact` clips on the F4.1 overlay, `sit_enter`→`sit_idle` on the base for `sit`, and releases the prop at the put_down target (or the actor's feet). Unapproved/missing/store-less props and capsule actors degrade with named skip lines while the composite window still elapses. Covered by `tests/test_interactions.py` (full suite 232 tests OK) plus VM headless evidence (see the F4 slice 2 Verified section): pick-up → drink → put-down end-to-end on the approved-GLB path, sit at a tavern chair with the seated speak layering over `Sitting_Idle_Loop`, capsule and prop-unavailable skip paths, and the standard demo byte-identical to its pre-change baseline. **With this slice, F4's implementable scope is complete**: layering, gaze, prop sockets and composite actions all execute end-to-end on VM evidence. **The F4 exit itself — composite actions completing without visible severe clipping, on owner hardware — remains open and unclaimed**: everything here is headless log evidence, which proves scheduling, attachment mechanics and clip routing, not on-screen appearance.

### F2 slice 2 — recipe composition + compatibility rules (2026-11-03, Linux VM)

- **Composition module** (`studio/recipes.py`): `assemble_character(library, spec, *, require_approved=False)` first shape-validates the spec via `validate_character` (shape errors re-raised as `RecipeError`, so every assembly failure is one exception type with a named reason), then checks each part in slot order (body_base, head, hair, outfit entries in list order): existence in the library, asset `kind` equals the slot's kind (body/head/hair/outfit), and rig agreement (an asset whose `rig_id` is non-null must equal the recipe's `rig_id`; null-rig parts fit any rig). ### F2 slice 4 — structured director-to-engine IPC contract (2026-11-03, Linux VM)

- **Contract module** (`studio/ipc.py`): constants `IPC_VERSION = "1.0.0"`, kinds `scene`/`result` in one place. `wrap_scene` validates the scene (via `studio.schema.validate_scene`) and wraps it with an ISO-8601 `issued_at` stamp; `unwrap_scene` refuses non-object envelopes, unknown keys, unknown `ipc_version`, unknown `kind`, missing/non-object payloads, and payloads failing full scene validation — every refusal an `IpcError` naming the reason. `write_ipc`/`read_ipc` are the file helpers; `make_result`/`validate_result`/`write_result`/`read_result` define the result document (`scene_id` must be a valid scene id, `accepted` a real boolean, `detail` a bounded string).
- **CLI + preview integration:** `studio demo` writes the runtime scene through `write_ipc` (same `godot/data/scene_runtime.json` path; the print line now notes the envelope). `godot/main.gd` treats a document carrying `ipc_version`/`kind` as an envelope: version/kind/payload-shape are checked, the payload then flows through the unchanged load validation; on success — and on each load-validation failure — it writes `scene_result.json` (shape above) when the load was enveloped. Bare scenes are deliberately NOT acknowledged (pre-IPC behavior byte-for-byte; result is the ack for an IPC message, and a bare file made no such request). `godot/data/scene_result.json` joins the other runtime documents in `.gitignore`. One pre-existing test (`test_f1_catalog.py` demo export) now reads the exported scene back through `read_ipc` — the export's wire shape is the thing this slice changed; its manifest assertions are untouched.
