# Underreach v0.10 — Slice 29C.2: Live Encounter Integration

## Purpose

Slice 29C.2 crosses the boundary that Slice 29C.1 deliberately stopped at. A deterministic 29C.1 encounter plan is still content scaffolding and is **not** allowed to decide combat outcomes. 29C.2 explicitly promotes one validated planned encounter into the existing authoritative deterministic combat simulation, records the resulting events in the Ledger, and proves that Unreal only presents those results.

The governing rule remains:

> THE SIMULATION CREATES THE EVENTS. THE PRESENTATION SYSTEM ONLY PRESENTS THEM.

## Authority boundary

The flow for this slice is:

```text
29C.1 non-authoritative encounter plan
        ↓ explicit promotion
Canonical EncounterState
        ↓
Existing deterministic combat_system.resolve_combat
        ↓
Authoritative Crawl state + Ledger events
        ↓
Canonical 29C.2 proof artifact
        ↓ read-only
Unreal presentation consumer
```

The 29C.1 plan remains `authoritative: false`. Promotion creates a real `EncounterState` inside the canonical Crawl model. Combat damage, health, deaths, retreats, injuries, monster defeat, encounter status, and the final outcome are then owned exclusively by the existing deterministic simulation.

Unreal does not call `resolve_combat`, does not generate a winner, and does not write the canonical artifact.

## Compatibility note

The existing simulation models still use internal `Crawl`, `Crawler`, and `Floor` names for persistence and protocol compatibility. New 29C.2 public-facing metadata uses Underreach terminology such as Descender, Sector, Stratum, and Ledger. This slice does not perform a risky serialization rename.

## Source binding

Promotion records the accepted 29C.1 identities in `EncounterState.trigger`:

- source encounter-plan digest
- source encounter ID
- source Sector ID
- source theme
- source monster-member IDs
- 29C.2 promotion protocol

The 29B Stratum/Sector graph remains a deterministic content/presentation graph at this point. Therefore, the canonical `EncounterState.location_id` uses an existing valid simulation `CrawlLocation`, while the source Underreach Sector remains explicitly bound in encounter metadata. A later traversal-domain migration can make Strata/Sectors canonical without breaking this boundary.

## Monster promotion

29C.1 monster definitions are converted deterministically into existing `EnemyState` objects. The mapping is stable and intentionally conservative for this integration proof:

| Monster family | Canonical enemy archetype |
| --- | --- |
| burrower | brute |
| stalker | stalker |
| thrall | skirmisher |
| hound | skirmisher |
| construct | guardian |

Health, attack, defense, accuracy, evasion, and initiative are deterministic functions of the 29C.1 threat value. This is an integration baseline, not final balance.

## Ledger proof

The live proof records `UNDERREACH_ENCOUNTER_PROMOTED` before invoking canonical combat. The existing combat engine then records events including `COMBAT_STARTED`, hits/damage, injuries where applicable, enemy defeats, Descender deaths or retreats where applicable, and `COMBAT_ENDED`.

The canonical JSON artifact contains:

- protocol `underreach.live-encounter-canonical.v1`
- `authoritative: true`
- source environment/theme/encounter-plan digests
- source Sector and encounter identity
- canonical encounter state before and after resolution
- deterministic `CombatResolution`
- final Descender state
- final monster state
- relevant Ledger events
- canonical Crawl fingerprint
- canonical truth digest
- a separate `underreach.live-encounter-presentation.v1` projection marked `authoritative: false`

The presentation projection is validated against canonical truth. It cannot add or remove defeated monsters, dead Descenders, retreats, change the outcome, change final state, or alter Ledger event identity/order.

## Unreal proof

`build_underreach_live_encounter_proof.py` is a read-only consumer of the canonical JSON generated by normal repository Python before Unreal starts.

The UE 5.8 proof:

- uses `-NullRHI -NoSound` for remote/headless validation;
- spawns one proxy actor for every canonical Descender in the proof;
- spawns one proxy actor for every canonical monster;
- tags actors with canonical identities/final states;
- verifies the presented defeated/dead/retreated sets exactly match simulation truth;
- verifies actor identity sets exactly match canonical state;
- verifies Ledger event IDs exactly match the presentation contract;
- hashes the canonical JSON before and after Unreal and requires byte-for-byte immutability.

Diagnostics are written to:

```text
unreal/CrawlPresentation/Generated/underreach-29c2/live-encounter-unreal-debug.json
```

The canonical source artifact is:

```text
unreal/CrawlPresentation/Generated/underreach-29c2/live-encounter-canonical.json
```

## Validation

Run:

```powershell
.\scripts\run-underreach-live-encounter-validation.ps1
```

Acceptance requires:

1. focused 29B.1 through 29C.2 deterministic tests pass;
2. identical canonical generation reproduces both canonical and proof digests;
3. the canonical artifact is authoritative and the presentation projection is not;
4. canonical Ledger contains promotion, combat start, and combat end;
5. resolution defeated/dead sets exactly agree with final simulation state;
6. presentation tampering is rejected by Python validation;
7. UE consumes the exact canonical digest;
8. UE actor sets exactly match canonical Descender and monster IDs;
9. UE defeated/dead/retreated presentation sets exactly match canonical resolution;
10. UE leaves the canonical JSON byte-for-byte unchanged;
11. fresh UE diagnostics report `all_pass`;
12. the full repository regression suite passes.

## Deliberately deferred

29C.2 does **not** claim production monster art or behavior. Deferred work includes:

- skeletal monster meshes and authored locomotion/attack/death animation;
- continuous tactical monster movement in Unreal;
- canonical Stratum/Sector traversal migration;
- multiple simultaneous live encounters across Sectors;
- encounter loot/reward presentation integration;
- richer encounter tactics and monster abilities;
- the later strategic/AI brain layer;
- final combat cinematography and Feed polish.

The purpose of 29C.2 is narrower and more important: establish a tested one-way boundary where encounter content becomes canonical simulation state, the simulation alone resolves the fight, the Ledger records what happened, and Unreal is provably unable to change the outcome.
